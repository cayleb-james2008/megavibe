## Rebuild requirements

The checklist below compares the public product scope with this Linux rebuild. “Partial” means a local equivalent exists, but depends on behavior or integrations not reproduced here.

| Public feature | Rebuild status | Evidence and boundary |
| --- | --- | --- |
| Native desktop, project workspaces, pan/zoom board | Implemented | Tauri 2 app, React Flow board, and local folder selection in `src/App.tsx` and `src-tauri/src/lib.rs`. |
| Interactive PTYs, prompt control, graceful stop, resume | Implemented with CLI limits | `portable-pty` process management, xterm UI, explicit start/stop, and a confirmed-close offer to relaunch consoles that were running. Claude Code and Gemini use app-assigned session IDs; Codex opens its CLI session picker on resume rather than guessing an ID from shared rollout files. Other executables can supply custom resume arguments. The last 128 KiB of scrollback is saved. A running PTY itself cannot survive app shutdown. Codex picker behavior is described by its [official CLI source](https://github.com/openai/codex/blob/main/codex-rs/cli/src/main.rs). |
| Notes, checklists, kanban, calendar, text, drawing, image markup | Implemented | Board card types in `src/BoardCard.tsx`; app-data persistence in `src/model.ts` and the Rust storage commands. |
| Web preview and inspector | Partial | User-entered HTTP(S) preview is sandboxed in an iframe. No embedded DOM or devtools inspector is included. |
| Teams, batch composer, handoffs, mission map | Local equivalents | Up to twelve consoles can be launched together. Handoff drafts summarize recent visible output locally, and require review. Mission statuses use output/permission-prompt heuristics plus manual override because CLI hook protocols are not configured or installed. @mentions are prepared into another running terminal without Enter; reports export role and status metadata. |
| Loops and prepared follow-up prompts | Local equivalent | Local schedule/idle/output rules queue bounded prompts while the app and target console are running. An exact marker line in new terminal output creates a completion candidate; the user confirms before the loop retires because a PTY may echo pasted prompt text. Megavibe does not infer semantic completion, plan with a hosted model, or auto-submit prompts. |
| Documents, diagrams, code tree, Markdown vault | Implemented with local parsing limits | Studios builds a repository brief locally, exports paginated PDF/Markdown, maps relative JS/TS imports, Rust modules, and Python imports into diagrams, highlights source previews, and stores Markdown files under project `.hypervibe/vault` (or app data for a personal workspace). The import graph is heuristic, not an AST or alias resolver; PDF glyphs outside the built-in font are normalized; vault listings are limited to 1,000 files, 16 directory levels, 1 MiB per file, and 16 MiB total, with an on-screen notice when files are omitted. Excalidraw interoperability was not checked against a separate Excalidraw app. |
| Git and GitHub tools | Implemented with explicit remote consent | Local status, staged commit, push, and pull are on the Git page; a board card polls local `git status`. A user can explicitly request repository, issue, and pull-request metadata via locally installed `gh`; the app asks before the request and fetches at most ten open issues and PRs. Push, pull, and GitHub metadata require confirmation. |
| Isolated CLI accounts | Partial | Profiles set CLI-specific HOME/XDG roots and do not copy credentials. They are directory isolation only, not an OS sandbox; the inherited process environment remains available. |
| Usage analytics | Implemented with format limits | `src/UsagePage.tsx` provides on-demand Claude/Codex/Gemini status checks and local day-by-CLI/profile token charts. Metadata-only parsers support selected Claude JSONL, Codex rollout JSONL, and Gemini session JSON/JSONL records; schemas remain best-effort and totals can be incomplete. See [`docs/USAGE.md`](USAGE.md). CLI status checks are user-triggered and may contact the CLI provider; local logs are never uploaded. |
| Voice input and spoken responses | Implemented as an on-device equivalent | The Voice page provides push-to-talk Whisper transcription, a local Qwen3 planner for notes/checklists/kanban, and bundled Flite spoken replies. Model downloads are explicit, revision-pinned, and SHA-256 checked; board updates require review. Terminal output is excluded from planner context. The planner is smaller than Hypervibe's hosted service and the bundled US-English voice is lower fidelity. See [`docs/VOICE.md`](VOICE.md). |
| Local project/global memory | Implemented | Explicitly saved text can be pasted into a selected running console without submitting it. |
| Global permission mode | Local equivalent | Default, edit auto-approval, and all-action auto-approval are applied at launch for Claude Code, Codex, and Gemini CLI only. Default is ask-as-configured. Enabling full auto-approval requires confirmation; custom CLI permission flags take precedence. |

## Verification record

- `npm run tauri -- build` — passed for the final source. The Debian package is 16.89 MiB. Vite reports the approximately 1.44 MB minified JavaScript bundle over its 500 kB advisory threshold.
- `cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check` and `git diff --check` — passed. A native release build compiled the Rust backend. No automated test suite was run.
- The Debian package was extracted and launched in a dedicated hidden X11 workspace. The Board and Voice pages rendered, and a local Bash PTY printed `Megavibe-PTY-smoke`; stopping it showed the confirmation dialog.
- The app's explicit voice setup downloaded the pinned Whisper base and Qwen3-4B models into the test profile. After setup the UI reported `Models ready · offline`. A typed request ran through local Qwen inference, generated a checklist in the review panel, and adding the approved change created a board card. The built-in `Speak reply` action ran without a planner/runtime error. Microphone capture and audible output were not verified because the isolated workspace has no user audio hardware.
- `ldd` on the extracted package resolved llama.cpp and ggml only from its bundled CPU libraries, with no unresolved libraries. The executable no longer exports Whisper's static `ggml_flash_attn_ext_add_sinks` symbol, which had interposed on llama.cpp during the first inference attempt.
- `npm run package:linux:tarball` — passed and produced a 12 MiB x86_64 archive with the native executable, CPU voice libraries, and notices.
- A trial AppImage build on this host was 989 MiB because linuxdeploy selected the host's GPU-enabled llama.cpp 0.6 runtime and its ROCm dependencies instead of Megavibe's bundled CPU runtime. The default bundle target is therefore Debian; the portable tarball is the release download for other Linux distributions.
- The fetched `origin/main` matched the local base before publication.

No authenticated Hypervibe account, packaged Hypervibe application, or private runtime was inspected. Exact CLI transcript schemas, hosted planning behavior, undocumented hooks, and GitHub panel behavior remain unknown. The matrix describes the rebuild's code paths, not a claim of full product parity.
